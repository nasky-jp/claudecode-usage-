# 業務改善プラン(KAIZEN PLAN)

作成日: 2026-07-02
対象: 兼業トレーダー(日本株)×自分で開発する人
ゴール: **朝夜の定型作業ゼロ化** — 自分は「判断」だけに集中する状態

---

## STEP 1: 業務マップ

### 1-1. 時間帯別の業務整理

| 区分 | 業務 | 入力 | 処理 | 出力 | 使うツール | 詰まりやすい点 |
|---|---|---|---|---|---|---|
| 日次(夜22時) | 米国市場チェック→翌日予測 | NASDAQ/ドル円/GOLD/セクターETF | 変化率確認→セクター連動の推論 | 夜間レポート | market_flow.analyze_night | **既に自動化済み**。ただし予測が当たったか誰も検証していない |
| 日次(朝8時) | 前夜予測と朝データの突合 | 夜間レポート+朝の市況 | 差分確認→今日の注目点3つ | 朝チェックレポート | market_flow.morning_check | **セクター名で止まる**。「半導体が強い」→「では何を買う?」の銘柄選定が手作業 |
| 日次(朝8時〜9時) | 銘柄選定・スクリーニング | 注目セクター+証券アプリ | セクター内の個別銘柄を目視で絞る | 監視リスト | 証券アプリ | **最大のボトルネック**。兼業なので朝の時間がない |
| 日次(引け後) | トレード記録 | 約定履歴 | Excelに手入力 | 売買記録 | Excel/シート | 面倒で続かない。「なぜ入ったか」が残らない |
| 週次(週末) | 振り返り | 1週間のレポート+売買記録 | 読み直し・勝敗分析 | (頭の中) | ファイルを開いて回る | レポートが散在。**読み直しに時間がかかり、学びが蓄積されない** |
| 月次 | 成績集計 | 売買記録 | 損益集計 | 月次成績 | Excel | 記録が不完全だと集計できない |
| 単発 | ツール開発・改善 | 思いつき | Python実装 | スクリプト | Claude Code | 何から作るべきかの整理がされていない(→本ドキュメントで解消) |

### 1-2. 人間がやるべき判断 vs AIに任せられる作業

**人間に残すべき判断(自動化しない):**
- 実際に発注するか/しないか(資金を動かす最終判断)
- ポジションサイズ・損切りライン
- 予測と実勢が食い違ったときの「見送る」判断

**AIに任せられる作業(自動化する):**
- データ取得・変化率計算・レポート生成(済)
- 予測→翌日実績の答え合わせ(**予測精度の自動採点**)
- 注目セクター→個別銘柄候補への展開(**スクリーナー**)
- 売買記録のフォーマット統一・損益計算(**日誌CLI**)
- 散在レポートの1画面統合(**ダッシュボード**)
- 週次振り返りの下書き生成(**週次レビュー**)

## STEP 2: 自動化/効率化の候補(15個)

> 実装難易度: 低/中/高、所要時間: Claude Codeで作る場合の目安、優先度: S/A/B/C

### 候補1: 朝の日本株スクリーナー
- 改善案: 夜間レポートの注目セクター→日本株の主要銘柄をギャップ率・モメンタム・出来高でランク付けし、朝チェックに監視リスト表を自動添付
- 解決する課題: 最大のボトルネック「セクター名から銘柄への落とし込み」が手作業
- 期待効果: 朝の銘柄選定 20〜30分 → 3分(候補一覧の確認だけ)
- 作るもの: `market_flow/screener.py` + セクター別銘柄ユニバース `universe.py`
- 実装難易度: 中 / 所要時間: 2h / リスク: ユニバースが古くなる(半期ごと見直しルールで対処)
- 優先度: **S**

### 候補2: 予測スコアカード(答え合わせ自動化)
- 改善案: 夜間予測の注目セクターTOP3が翌日実際に上位だったかを自動採点しCSVに蓄積
- 解決する課題: 予測が当たっているのか誰も検証しておらず、システムを信じてよいか分からない
- 期待効果: 「AIの予測をどこまで信用するか」が数字で決められる。プロンプト改善のPDCAが回る
- 作るもの: `market_flow/scorecard.py` + `reports/scorecard.csv`
- 実装難易度: 中 / 所要時間: 2h / リスク: セクター名の表記ゆれ(構造化出力で対処)
- 優先度: **S**

### 候補3: トレード日誌CLI
- 改善案: `python3 -m market_flow.journal add 8035 --side buy ...` の1コマンドで売買記録。Excel互換CSV、損益自動計算
- 解決する課題: Excel手入力が面倒で記録が続かない。「なぜ入ったか」が残らない
- 期待効果: 記録1件 3分 → 15秒。振り返りの原データが必ず揃う
- 作るもの: `market_flow/journal.py` + `journal/trades.csv`
- 実装難易度: 低 / 所要時間: 1.5h / リスク: 入力忘れ(朝チェックにリマインド行を出して対処)
- 優先度: **S**

### 候補4: 統合ダッシュボード
- 改善案: 最新の夜間レポート・朝チェック・スクリーナー結果・予測精度・日誌サマリーを1枚のHTMLに自動生成
- 解決する課題: レポートが日付ファイルで散在し、読み直し・整理に時間がかかる
- 期待効果: 「ファイルを探して開く」時間ゼロ。朝はダッシュボード1枚を見るだけ
- 作るもの: `market_flow/dashboard.py` → `reports/dashboard.html`
- 実装難易度: 低 / 所要時間: 1.5h / リスク: ほぼなし(生成物は毎回上書きの読み取り専用ビュー)
- 優先度: **A**(②とセットで実装)

### 候補5: 週次レビュー自動生成
- 改善案: 1週間分のスコアカード+日誌+レポートを集約し、Claudeが「今週の勝ちパターン/負けパターン」を下書き
- 解決する課題: 週末の振り返りが「読み直すだけで終わる」
- 期待効果: 振り返り 1h → 15分(下書きに追記するだけ)
- 作るもの: `market_flow/weekly_review.py`
- 実装難易度: 中 / 所要時間: 1h / リスク: API課金(週1回・少額。実行は手動起点)
- 優先度: **A**

### 候補6: 夜間分析の構造化出力
- 改善案: 夜間レポートに機械可読の `TOP_SECTORS:` 行を追加し、下流(スコアカード・スクリーナー)が確実にパースできるようにする
- 解決する課題: 自由文レポートは後工程で再利用できない
- 期待効果: 候補1・2の前提。パイプライン化の土台
- 作るもの: `analyze_night.py` のプロンプト改修+パーサー
- 実装難易度: 低 / 所要時間: 0.5h / リスク: 旧レポートは形式が違う(フォールバック実装で対処)
- 優先度: **S**(候補1・2の依存)

### 候補7: データ取得のリトライ・冗長化
- 改善案: yfinance失敗時に指数バックオフでリトライ。日経は現物(^N225)に加えCME先物(NKD=F)も取得
- 解決する課題: 夜間cronが単発の取得失敗で「取得失敗」だらけのレポートを作る
- 期待効果: 無人実行の信頼性向上
- 作るもの: `fetch_market.py` 改修
- 実装難易度: 低 / 所要時間: 0.5h / リスク: なし
- 優先度: **A**

### 候補8: Claude Code Skills化
- 改善案: `/trade-journal`(対話で日誌記入)、`/weekly-review`、`/morning-brief` をリポジトリSkillとして整備
- 解決する課題: コマンド引数を覚えられない。自然文で頼みたい
- 期待効果: 「昨日のトヨタ買い100株を記録して」で日誌がつく
- 作るもの: `.claude/skills/*/SKILL.md`
- 実装難易度: 低 / 所要時間: 1h / リスク: なし
- 優先度: **A**

### 候補9: 運用SOP・チェックリスト整備
- 改善案: 朝5分・夜3分・週末15分の定型手順書と、障害時(データ取得失敗・APIエラー)の対応表
- 解決する課題: 「今日は何をどの順でやるか」を毎回考えている
- 期待効果: 定型作業の認知負荷ゼロ化。将来の自分への引き継ぎ書
- 作るもの: `docs/OPERATIONS.md`
- 実装難易度: 低 / 所要時間: 0.5h / リスク: なし
- 優先度: **A**

### 候補10: レポート保管・命名ルールの整備
- 改善案: `YYYYMMDD_night_report.md` 等の既存規約を明文化し、古いレポートの月次アーカイブ方針を決める
- 解決する課題: reports/ が肥大化していく
- 期待効果: 検索性維持。ダッシュボードの表示も安定
- 作るもの: OPERATIONS.md内の運用ルール節
- 実装難易度: 低 / 所要時間: 0.2h / リスク: なし
- 優先度: **B**

### 候補11: 決算・経済指標カレンダー連携
- 改善案: 保有銘柄・監視銘柄の決算日と主要経済指標(FOMC・雇用統計・CPI)を夜間レポートに自動注記
- 解決する課題: 「明日決算だと知らずに持ち越す」事故
- 期待効果: イベントリスクの見落としゼロ
- 作るもの: カレンダーデータ取得+レポート注記(データソース選定が必要)
- 実装難易度: 高 / 所要時間: 4h+ / リスク: 信頼できる無料データソースが限られる
- 優先度: **B**(次フェーズ)

### 候補12: 予測精度に基づくプロンプト自動改善
- 改善案: スコアカードが一定件数たまったら、外れたケースの共通点をClaudeに分析させ、夜間分析プロンプトの改善案を出させる
- 解決する課題: 予測プロンプトが感覚で書かれたまま固定
- 期待効果: システムが自己改善するループ
- 作るもの: `prompt_tuner.py`(スコアカード30件以上たまってから)
- 実装難易度: 高 / 所要時間: 3h / リスク: 過学習的な改悪(人間レビュー必須にする)
- 優先度: **B**(データ蓄積後)

### 候補13: 通知連携(メール/プッシュ)
- 改善案: 朝チェック完了時にダッシュボードURLや要約を通知
- 解決する課題: レポートが生成されてもファイルを開きに行く必要がある
- 期待効果: 通勤中にスマホで確認できる
- 作るもの: Gmail下書き生成 or 通知スクリプト
- 実装難易度: 中 / 所要時間: 2h / リスク: **外部送信を伴うため要事前確認**。誤送信対策必須
- 優先度: **B**(要相談)

### 候補14: 月次成績レポート自動生成
- 改善案: 日誌CSVから月次の勝率・損益・セクター別成績・保有期間分析を自動集計
- 解決する課題: 月次集計が手作業
- 期待効果: 月初5分で先月の成績が出る
- 作るもの: `journal.py summary --month` の拡張
- 実装難易度: 低 / 所要時間: 1h / リスク: なし
- 優先度: **B**(日誌が回り始めてから)

### 候補15: バックテスト基盤
- 改善案: 「注目セクター上位を翌日寄りで買い引けで売る」等の機械的戦略を過去データで検証
- 解決する課題: 予測が当たっても収益になるかは別問題
- 期待効果: 戦略の期待値が事前に分かる
- 作るもの: `backtest.py`
- 実装難易度: 高 / 所要時間: 6h+ / リスク: 過去データの生存バイアス。結果の過信
- 優先度: **C**(スコアカードで精度を確認してから)

### 候補16: オフラインQA自動化
- 改善案: ネットワーク・APIキーなしで全モジュールの動作を検証するセルフテスト
- 解決する課題: cron無人実行のコードを手動でしか確認できない
- 期待効果: 改修のたびに30秒で回帰確認
- 作るもの: `market_flow/selftest.py`
- 実装難易度: 低 / 所要時間: 1h / リスク: なし
- 優先度: **A**
